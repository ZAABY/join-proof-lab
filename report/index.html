What the monthly checks actually establish

The naive plan fails 22 of 25 nonempty purchase-month populations. Explicit preaggregation passes all 25. Independently executed DuckDB joins match the audit predictions for all 26 populations and both plans: 52 plan comparisons.

Evidence, not a universal certificate

  • Supported: declared root-key star equijoins, exact text keys, mixed left/inner joins, explicit null and decimal rules.
  • Not supported: arbitrary SQL, filters, key coercion, cyclic/range/chained-child joins or automatic repairs. A passing contract does not prove that source values are true or that keys mean the same entity.
  • Run IDs bind versions, contract, exact input fingerprints and witness policy. Attempts have separate real timestamps. Local hashes detect inconsistent evidence; they are not signatures or tamper-proof records.
  • Files and grouping state are held in memory. No warehouse-scale speed or memory claim is made. Preaggregation is an explicit user-selected plan, not an inferred business rule.
